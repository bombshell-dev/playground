# Observation and document selection

`MutationObserver` delivers attribute, character-data, and child-list records in a microtask. Registrations belong to explicitly observed nodes, including detached trees. `subtree`, attribute filters, optional old values, overlapping registrations, `takeRecords()`, `disconnect()`, and updates to existing registrations are tested. Removed descendants remain observable through the next observer delivery, including when `childList` was not requested. Delivery snapshots are taken for each observer in notification order, so one observer's callback can add records to another observer that has not yet run.

The host invalidation callback is separate. Suppressing frames for detached preparation never suppresses mutation records. A callback exception is reported through the document of its first record, using `DocumentOptions.reportError`; it does not abort later observer delivery. This explicitly chooses a host for an observer that has no ambient browser realm. Record collections are frozen arrays, rather than a browser NodeList implementation. Registered targets are weakly retained by an observer; live target nodes retain their own registrations.

`document.createRange()` creates a live Range, initially collapsed at `(document, 0)`. Character-data offsets count UTF-16 code units; other node offsets count children. Ranges update when nodes are inserted, moved, removed, split, or edited. A move uses the standard remove/insert behavior: a boundary inside the moved subtree relocates to its former parent position. It does not follow the moved subtree. Existing nodes, listeners, and user state still retain their identities.

Implemented Range operations are boundary getters/setters and before/after variants, common ancestor, collapse, node/content selection, comparisons and point/intersection queries, cloneRange, stringification, deleteContents, cloneContents, and extractContents. Extraction moves fully contained nodes by identity and clones partial ancestor shells. The legacy detach method is a standard no-op and does not stop boundary updates. `insertNode`, `surroundContents`, contextual fragment parsing, StaticRange, normalize-related boundary merging, and geometry APIs are not implemented.

Each document owns one Selection backed by a live Range. Tested APIs are add/remove ranges, getRangeAt, collapse/setPosition, collapseToStart/End, setBaseAndExtent, extend, selectAllChildren, deleteFromDocument, and stringification. Explicit selection operations and live changes to its range invalidate the host's selection state. Selection is limited to the document tree; shadow selection and getComposedRanges are unfinished. Selection stringification returns the range's logical text because this package has no CSS rendering engine. Input/textarea value selection is a separate subsystem described in [focus-and-controls.md](focus-and-controls.md).

The implementation and tests are original. Normative sources consulted: [WHATWG mutation observers](https://dom.spec.whatwg.org/#mutation-observers), [live ranges](https://dom.spec.whatwg.org/#interface-range), and [Selection API](https://w3c.github.io/selection-api/). Relevant WPT source inspected: [MutationObserver childList](https://github.com/web-platform-tests/wpt/blob/master/dom/nodes/MutationObserver-childList.html), [attributes](https://github.com/web-platform-tests/wpt/blob/master/dom/nodes/MutationObserver-attributes.html), and [Range setting](https://github.com/web-platform-tests/wpt/blob/master/dom/ranges/Range-set.html). These observations do not claim the full WPT observer/range suite has been executed.
